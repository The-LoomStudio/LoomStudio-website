# Website CDP 内存初步调研

> 已归档（2026-11-04）：本次调查与修复已收束。正文保留各阶段证据，不代表每条旧结论仍成立；最终结果见网络与性能记录末尾，未完成项见[后续待办](../../issues/website-cdp-followups.md)。

日期：2026-11-04。状态：初始调研已完成；首批修复及验收结果见[网络与性能调研](website-cdp-network-performance-investigation-2026-11-04.md#首批修复与复验结果)。以下初始取证保留原时点口径。

## 范围与方法

复用 LoomStudio 的 `docs/guide/frontend-cdp-diagnostics.md` 流程，检查 Website 当前源码、9 月审计记录及 Chrome 中的线上 `https://loomstudio.pages.dev/`。保留用户原页，只在自建临时页滚动与导航；没有修改实现、刷新用户页、强制 GC、进行堆转储或部署。临时页已关闭，本轮开启的 Performance 域已关闭。线上构建与本地提交尚未核对一致性。

Website 是 Astro 静态输出，但首页有 React islands、Motion、Canvas 和交互演示，静态托管不代表零运行时成本。9 月已有源码审计，不能称为从未审计；旧问题状态也不能直接作为当前事实，例如当前 DocsLayout 已有请求去重和 navigationGeneration。

## 现场基线与口径

- 用户已有首页：视口 1440×900、DPR 2；1443 个 DOM 元素、119 个 img；26 个已加载唯一 currentSrc，DOM naturalWidth×naturalHeight×4 的原始读数约 43.8 MiB；后续确认该尺寸受srcset密度修正，不能将此读数用作物理像素预算，见网络与性能调研的口径校准。JS used heap 约 10.0 MiB。这是已有页面样本，不是冷启动。
- 自建首页滚动至底部后：15 个 BranchReveal 均已 hydration，页面共 17 个 Canvas；JS used heap 约 24.0 MiB。这与上一项不是严格 A/B，不将差值解释成泄漏或特效独占成本。
- 自建页导航到文档概览：517 个 DOM 元素、1 篇正文、20 个 img、0 个 Canvas。没有执行整套连续阅读增长实验。跨文档导航后的即时 heap 可能包含尚未 GC 的前页对象，不用它量化文档自身内存。
- 图片DOM natural尺寸不一定是源文件物理尺寸，原乘积不代表源图RGBA预算，更不是实测解码驻留、GPU 内存或进程 footprint。没有取得图层字节、retained size 和长期泄漏证据。

## 值得优先处理的路径

### 1. 故事揭示效果的离屏 Canvas

`src/components/branch-reveal/BranchReveal.tsx` 为每张图创建三档 440 像素宽的离屏 Canvas，保存在 React state；滚动完成并不会释放。15 张图当前页面 Canvas 高度合计 5450，三档离屏位图的单层 RGBA 预算为 `440×5450×4×3`，约 27.4 MiB。页面上的输出 Canvas 另计约 9.1 MiB。这些是尺寸预算，浏览器可能采取延迟分配等策略，不能承诺等额节省。

同组件每个实例注册 scroll/resize，挂载后每次滚动都会测量位置；即使 progress 已达到边界也仍执行测量。停止或减少无关实例工作有 CPU 收益候选，但尚未计时。

建议先保留现有视觉，评估按当前档位生成/持有位图，以及远离视口时释放可重建缓存。效果支持向上滚动反向播放，不能直接在第一次完成时永久销毁，也不应为此增加全局缓存管理器。以实际往返滚动确认重建成本和动画连续性后再定方案。

### 2. 效果采样绕开响应式图片选择

BranchReveal 的 `new Image().src = image.src` 直接请求 fallback 最大候选，未使用展示 img 已选择的 currentSrc；BrandAsciiReveal 也直接使用传入 src。首页现场同时出现同一插画的 832×1216 与 800×1169 两种 URL，说明存在不同尺寸版本同时加载的样本，但尚未通过 Network initiator 完整归因。

建议优先复用已经加载的展示图采样，或给低分辨率采样提供适当来源。采样最终仅几十列，没有必要另为它加载更大的版本。无需破坏原图或降低放大查看清晰度。

### 3. 放大图关闭后仍保留 src

`src/components/illustration/ZoomImage.tsx` 打开时才为弹窗 img 设置 src，避免了初始大图加载；但 finish 关闭 dialog 后没有移除该 src。访问过的多个弹窗会继续持有图像元素和资源引用。它不是已证实泄漏，浏览器也可能回收解码缓存。

建议关闭动画结束后移除弹窗图片 src，再验证再次打开、关闭时 decode 晚回包和重复开关。用多个不同图片的打开/关闭样本验证资源持有与回收，不以单次 heap 波动定论。

### 4. 文档连续阅读的 DOM 保留

DocsLayout 会追加全文并保留已读正文及引入的样式。目前文档总集合有限，这不是无限泄漏证据；现场初始只有 1 篇，也没有显示迫切需要虚拟化。

建议先记录读完整套文档后的正文/节点规模及滚动工作量，再决定是否需要 content-visibility 或其他措施。content-visibility 可减少离屏布局绘制，不会释放正文 DOM；不能把它描述成完整内存回收。暂不引入复杂文档虚拟化。

## 图片与特效的优化边界

`src/lib/site-images.ts` 已生成 WebP、srcset，限制候选不超过原图；ZoomImage 使用 sizes、lazy 和 async decode，原图留给放大。现场角色卡约333×464 CSS像素；此前读取的360×501为DOM密度修正尺寸，不能用来判断候选源文件尺寸。后续独立源图核对中该候选为376×524物理像素，同样不支持继续统一缩小。

不建议第一步批量压缩/缩小/裁切素材。编码压缩主要影响传输和文件大小；相同解码尺寸不会因此按同样比例减少像素内存。优先消除重复尺寸请求、临时位图常驻和已关闭预览的持有，再定向校准 sizes。已有 Hero 离屏暂停、演示可见性门控和岛屿延迟 hydration，应复用，而非重建一套效果调度框架。

## 后续验收

分别比较首屏、完整浏览后、回到顶部空闲、连续开关多张大图、完整文档阅读；记录页面可见状态和图片/Canvas/DOM规模。需要区分 JS heap、Canvas/图片预算与进程/GPU口径。验证反向滚动、再次打开、后台恢复和 reduced-motion，主观画质与动画体验由用户验收。本轮没有 CPU profile、完整 Network 瀑布、真实 GPU 内存和长期重复周期证据，不承诺具体节省量。

开发页面存在 Vite/HMR 和 Astro toolbar，图片由开发 image service 生成，不能与线上生产 heap 直接比较。首次入场遮罩后来正常结束；开始取样前检查到 error/warn 日志为空。

### 已确认的资源持有

通过 `Runtime.queryObjects(HTMLCanvasElement.prototype)` 和紧凑的实例聚合检查当前 realm：

| 状态 | Canvas 总实例 | 未连接 DOM 的实例 | 未连接实例像素预算 |
| --- | ---: | ---: | ---: |
| 进入故事区，仅前三张完成 hydration | 27 | 10 | 10.22 MiB |
| 逐段经过全部 15 张故事图 | 63 | 46 | 28.00 MiB |

完整样本的未连接尺寸为 `440×640` 9 张、`440×300` 15 张、`440×290` 21 张、`440×330` 1 张。前三组与 15 个 BranchReveal 各三档缓存对应，共 45 张；最后一张对应品牌位图。页面可见树中另有 17 张输出 Canvas。这里“未连接 DOM”包括有意作为缓存使用的离屏画布，不等同于泄漏节点。queryObjects 会影响 GC，所得实例和像素预算不是自然峰值或 retained bytes；本轮所有该组 RemoteObject 均已释放。

直接跳到页底会略过延迟 hydration 的区域，所以实际按故事区偏移 700/1400/2100/2800/3500 像素逐段经过，已 hydration 数依次为 6/9/13/15/15。后续复验应复用这种覆盖方式，不将跳底视为完整浏览。

真实点击“高处远眺城市与城堡”预览，打开后图片自然尺寸为 2560×1707；点击关闭并等到 DOM 确认 dialog.open=false 后，同一隐藏弹窗 img 仍有 src，naturalWidth/Height 仍为 2560×1707。确认了关闭后继续持有已加载大图，尚未量化其实际解码/GPU常驻。该图单层 RGBA 预算约 16.67 MiB；不能直接承诺关闭可回收同等进程内存。

### 文档规模反证

在同一临时页导航到 `/docs`，通过真实连续阅读哨兵逐次触发，直到 `data-state=end`：初始 1 篇、546 个 DOM 元素、正文 textContent 920 字符；结束 9 篇、983 个元素、正文 7744 字符。中间观察到 2/4/5/6/7/8/9 篇依次追加，没有把未完成的异步读数当终态。当前规模不支持优先引入文档虚拟化。

探针曾把 `data-docs-stream-status` 误写成 `data-doc-stream-status`，批处理产生 5 条探针 TypeError；核对源码选择器后更正，未触发业务动作。这些错误不是产品异常，不计入应用错误结论。

### 下一步最小范围

1. 优先研究 BranchReveal 减少三档位图同时持有的实现，同时保留反向滚动与字形过渡；以 45 张离屏画布为明确复验基线。
2. ZoomImage 在关闭动画结束后解除大图引用，并覆盖关闭期间 decode 晚回包、再次打开和切图，不改变放大清晰度。
3. 对特效采样另开有界 Network 窗口核对 currentSrc 与 fallback 最大候选，证实归因后再消除重复。首轮仅捕获进入故事区的 22 个 Image 请求（事件无截断），未完成逐图 initiator/尺寸配对，因此尚不能量化重复请求收益。
4. 文档暂不做内存结构改造，也不批量缩小或裁切素材。完整往返周期、后台恢复与 reduced-motion 留待实际修复验收。
