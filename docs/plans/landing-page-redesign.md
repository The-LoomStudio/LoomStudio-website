## 1. 核心定位与设计哲学转变

### 1.1 从“工具架构”到“创作者武器库与超限游玩体验”
此前面向发布页的设计容易陷入“开发者系统视角”——把时间线、上下文拼装画成冰冷的编译器流水线或 Git 分支图。对于 SillyTavern 迁移用户与 AI Role-play 创作者而言，他们真正关心的是：
- **游玩沉浸感**：告别纯文字聊天气泡，拥有媲美视觉小说/独立 RPG 的视听与状态表现力；
- **创作自由度**：改卡不伤原卡设定，随意挂载共享世界观与分支剧情；
- **脚本与扩展渲染**：数值判定、好感度、动态立绘与自定义 UI 界面。

### 1.2 现有发布页短板诊断
1. **Hero 顶屏过重且脱离产品**：100svh 纯风景插画轮播像一道静态幕布，未传递任何产品核心价值与玩法魔力。
2. **角色卡资源仅作为图片跑马灯**：点击仅放大静态 PNG，未展示角色的开场白、氛围联动、扩展渲染及状态机制。
3. **主会话与正文关系陈旧**：未同步主应用“主 Session 已融入正文折叠展现”的最新形态，缺少辅助 Agent（文生图、检定等）的协作实感。
4. **架构地图占据主屏**：开发者架构图放发布页偏离受众，属于低转化冗余模块。

## 2. 四大核心体验展区设计

### 模块 A：首屏 Living Hero（有呼吸感的叙事门面）

- **空间规划**：打破死板的 100svh 封闭插画墙，底部采用露出式（Peak Preview）设计，自然衔接下方的跑马灯。
- **视觉主体**：
  - 看板娘 Nom 分层动态立绘作为前景；
  - 背后衬以轻微流光的 `LOOM STUDIO` Display 艺术大字与核心标语（“超越传统酒馆的 AI 互动叙事工作台”）；
- **浮动叙事视窗（Live RP Peek）**：
  在看板娘身旁放置一个半浮动的交互视窗，呈现正在运行的微型实感叙事：
  - 小说级正文逐字渐现；
  - 正文中半透明的会话折叠指示；
  - 辅助 Agent 刚刚为当前剧情生成的场景插画直接嵌入在正文边缘。

### 模块 C2：非侵入式设定与世界派生（创作者无损定制）

解决传统酒馆改卡“改乱原作者设定、多卡共享世界观困难”的巨大痛点：

#### 概念线框图：
```text
               ┌─────────────────────────────┐
               │    共享世界观 (Lorebook)    │ ◄─ 一套世界设定，
               │   《克苏鲁都市：新约》      │    可同时赋能给多张角色卡
               └──────────────┬──────────────┘
                              │
               ┌──────────────▼──────────────┐
               │    我的私设层 (Overlay)     │ ◄─ 独立覆盖层：私有关系、
               │   性格微调 / 专属剧情记忆   │    新增分支，随时一键剥离
               └──────────────┬──────────────┘
                              │
               ┌──────────────▼──────────────┐
               │    原作角色卡 (Base Card)   │ ◄─ 原始设定只读受保护，
               │    完整封装 · 随时无损重置  │    原作者更新可无缝同步
               └─────────────────────────────┘
```

- **展现重点**：
  - 积木式层叠结构：用户可以自由修改，永远不会污染或搞丢最初下载的原版角色卡；
  - 真正的世界构建：一个庞大世界设定无需在几十个角色卡中复制粘贴几十遍。

## 当前设备演示调整（2026-10-27）

以最新实现为准：瀑布流最后一张固定为 Nom，头像使用同一张图片；演示背景复用 nom-banner-013。滚动只推进故事正文，HTML 渲染、纸页/潮汐主题和 The World 均由按钮打开。天气按钮控制设备内外共用背景的日落色调或云层与雨幕，云层复用网站 CloudField；它是本地视觉示例，不调用真实扩展或模型。设备边框保持实体，毛玻璃只用于内容面板。
