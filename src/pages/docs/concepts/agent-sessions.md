## 独立的推演空间

Agent Session 保存工作身份与 Transcript；普通 Session 可以关联 Timeline，也可以独立存在。每条 Timeline 另有一个与 Timeline 同 ID 的根 Session，承接故事输入框的扮演与讨论，并共享该故事的工作历史。

Agent Session 可以容纳：

- 用户输入与 Agent 的交互消息
- 工具调用与执行结果（Tool Calls & Results）
- 思考步骤、推演草稿与运行状态
- 与正文提交相关的版本标记
- 仅属于工作过程的临时备忘与中间观察

## 为什么不直接等同于聊天记录

模型接口里的 `messages[]` 只是一次网络请求的传输外形，不该被当作核心的数据存储模型。Loom Studio 会在每轮推演前，按预设、挂载和激活规则组织正文、设定与工作历史，编译为所选模型的请求格式。

长期记录与模型协议分开保存；后续请求采用哪些历史，取决于预设及摘要配置，不代表每次都会自动压缩。

## 提交至正文的秩序

源码版中，扮演输入先提交为正文节点，再以节点 ID 启动根 Session 的执行；讨论直接进入同一会话的工作历史。

故事根 Session 按正文模式采用 Assistant 文本：声明式模式通过 `declare_narrative` 声明下一条完整回复为正文；自动模式在扮演执行中采用普通 Assistant 文本。讨论、工具结果和推理内容不进入正文。普通副 Session 的回复也不会仅因关联故事就成为正文。

正文写入与整轮 Run 不是一个整体事务，后续失败不会撤回已提交内容。以上按源码版说明，下载版本以对应发行说明为准。

## 丰富的工作形态

不同的预设配置可以赋予 Agent 截然不同的工作方式：沉浸式角色扮演、剧情续写、世界观合理性推演、章节精修或是挂载外部检索工具。系统提供了高度包容的底层能力，从不把死板的工作流强加给创作者
