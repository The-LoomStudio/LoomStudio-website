## 三层生命周期模型

Loom Studio 不采用“单个脚本即插件”的简陋模式，而是将扩展拆解为三层清晰的生命周期：

~~~text
Extension Package
  安装分发、版本管理与持久数据归属
  ↓
Extension Module
  运行环境、代码入口、启用状态与能力授权
  ↓
Extension Instance
  单次激活、事件注册与生命周期上下文
~~~

- **Package（扩展包）**：分发与分享的最小单元，一个包可以纯粹包含角色卡设定、世界书与提示词模板，也可以同时携带服务端或前端可执行模块
- **Module（功能模块）**：运行时的边界划分，后端模块提供数据工具与扩展能力，前端模块负责界面挂载与交互组件
- **Instance（运行实例）**：实际执行的生命周期实体，当插件热重载或停用时，对应的所有事件监听与资源占用会被确定性回收，根绝内存泄漏与幽灵监听

## 服务端与前端隔离

服务端与客户端拥有完全不同的环境与安全边界：

- **Server Host**：管理后台模块的生命周期、事件订阅与存储，负责数据校验与模型工具对接
- **Client Host**：管理前端渲染模块，通过规范的界面协议，让插件能够优雅地向工作区注入自定义面板与交互卡片

## 声明式 Manifest

扩展通过 `manifest.json` 显式声明其所需能力与交互范围，未经声明的操作在运行时将无法执行

多个插件共存时的优先级与依赖关系完全透明，杜绝隐蔽的全局状态污染与未知冲突，让生态扩展真正做到即插即用、安全可靠
