## 存储结构与装配链路

在传统的提示词管理中，创作者常常被迫把“平时如何分类存放”与“最终以什么顺序塞给模型”混在同一个文件列表里

Loom Studio 将两者清晰区分：

- **资源树（Resource Tree）**：关注**内容如何组织**，如世界观设定、人物小传、道具词条与全局规则
- **装配骨架（Composition Skeleton）**：关注**上下文如何装配**，声明挂载槽位、排序权重与预算边界

~~~text
Resource Tree (内容如何归档)
  ├── 角色卡 / 艾莉丝
  └── 世界观 / 浮空城
        ↓ 声明挂载目标与条件
Composition Skeleton (提示词如何装配)
  ├── [系统指令槽] System Prompt
  ├── [世界设定挂载点] 世界观 ← 浮空城
  ├── [角色定义挂载点] 角色设定 ← 艾莉丝
  └── [剧情历史槽] Narrative Timeline
~~~

## 挂载点（Mount Point）与槽位（Slot）

装配骨架由灵活的**挂载点（Mount Point）**与**槽位（Slot）**构成，不设硬编码限制：

- **槽位（Slot）**：提示词上下文中的装配单元，声明所处的角色（System / User / Assistant）、先后排序与 Token 预算
- **挂载点（Mount Point）**：允许外部资源或扩展插件注入内容的锚点
- **注入绑定（Injection Binding）**：设定词条只需声明自己的挂载目标，装配引擎就会在编译时将其投影至对应槽位，无需反复修改整体模板

## 动态激活（Activation）

并非所有已挂载的设定都会无条件塞入模型上下文，激活引擎会在每轮对话中动态求值：

- **关键词唤醒**：当前剧情上下文或输入命中了词条设定的触发词
- **状态条件匹配**：世界线状态（如好感度、场景位置、章节阶段）满足预设规则
- **运行时沉淀**：Agent 在推演过程中主动检索到的知识，按需注入到动态槽位

未激活的设定词条会被安全略过，既保持提示词紧凑高效，也避免无关背景分散注意力
